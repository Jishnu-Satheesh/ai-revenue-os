# Independent Creative Studio — proposed technical contract

Status: PROPOSED, awaiting user approval of the design and execution plan. Updated 2026-09-21. Every new table, RPC, permission, event and API below is a proposal, not a claim about deployed capabilities. Read with `docs/superpowers/specs/2026-09-20-independent-creative-studio-design.md`, `current-studio-audit.md` and `provider-and-assets-audit.md`.

## 1. Binding product boundaries

- A campaign is optional. Generate persists organization-owned Studio history. Selected campaign automatically receives a durable selected-creative link after successful generation; this grants no approval, publishing or spending authority.
- The model creates the COMPLETE poster, including the user's Text Copy verbatim. Preserve the submitted Unicode string and line breaks; no trim/paraphrase/translation as a hidden preprocessing step. Model instruction is not proof: full-size human spelling/layout review is required, with OCR findings as fallible assistance.
- Actual, independently displayable, progressively refined image previews are required. Text progress, a loading animation, pixel reveal of a final image, or raw undecodable base64 chunks do not satisfy this requirement.
- Provider qualification is a prerequisite. Use a provider/model/API profile that proves both partial frames and original-context marker edits. Qualify an alternate provider if Gemini cannot satisfy both. No model name is hardcoded by this design.
- Marker edits regenerate the full poster using its pinned provider/model and original continuation. Markers indicate change intent, not a guaranteed pixel mask. Keep earlier versions; review the entire child poster.
- This path deliberately supersedes Spec 020's no-model-text/plate-only rule for standalone Studio only. Existing Campaign deterministic compositor/digests remain unchanged. Exact design means close reference adherence, never a pixel/text/logo guarantee.

## 2. Domain contracts and limits

New domain root: `src/domain/creative-studio/`; application/infrastructure root: `src/modules/creative-studio/`; public exports: `src/modules/creative-studio/index.ts`. UUIDs are typed IDs; hashes are lowercase SHA-256; dates are UTC; all database identities include organization ID.

- `StudioDraft`: documentId; baseRevision integer; campaignId nullable; mode `exact_design | take_inspiration`; prompt string 0–6000 in saved drafts/New Idea (Enhance and image generation require nonblank creative direction); textCopy string 0–6000; aspectPreset from the versioned preset registry below; primaryReferenceId nullable (manifest reference identity, including uploads); channelLogoSubstitutions array; references; productVersionIds; brandSnapshotId. Proposed Instagram Feed default is 4:5, intended export 1080×1350; other initial presets are Instagram Stories 1080×1920, Google square 1200×1200, Google horizontal 1200×628, Google vertical 960×1200 and generic ecommerce creative 1200×1200, with an optional Instagram Feed 1440×1800 export. Follow the provider audit preset table; Amazon remains unavailable until a named current placement is qualified. Provider-native dimensions are recorded separately. Non-native ratios use explicitly previewed contain/pad with approved brand-compatible color by default; crop requires a user-approved crop preview and text/logo-bound checks. Never stretch or silently crop. Unsupported profile/preset pairs remain visibly unavailable.
- `StudioReference`: each has a unique immutable manifest `referenceId`, then discriminated `approved_history(versionId,reviewId,hash) | uploaded_reference(uploadId,rightsAttestationId,hash) | product(versionId,hash) | brand_mark(versionId,hash)`. At most three design references (approved plus uploaded), three products and two marks, further narrowed by qualified provider total capacity including parent and marker overlay. No rejected-history type at final generation.
- `ChannelLogoSubstitution`: exact original-copy range `{start,end,phrase}` in Unicode code-point offsets, known channel ID, approved logo asset version/hash and explicit selected-chip consent. Reject overlapping ranges, phrase mismatch, unavailable bytes and unsupported channel; retain original copy plus manifest, never replace its stored text. Derived rendering instructions omit only the explicitly represented phrase. Exact design requires primaryReferenceId to resolve to a selected approved_history or uploaded_reference entry, so upload-only Exact design works without inventing an Asset Library version.
- `StudioMarkers`: at most eight ordered entries `{ordinal,x,y,instruction}`; coordinates finite in [0,1] against EXIF-normalized original image; instruction 1–500 characters. Send the clean parent plus a separately rendered numbered overlay, never overwrite source bytes. Empty instructions, duplicate ordinals and off-image points refuse before admission.
- `StudioProviderProfile`: provider, exactModelId, apiFamily, adapterVersion, supportedRatios, maxInputBytes, maxImages, partialFrameContract, continuationContract, retentionDisclosure, measuredQualificationId, enabled. Immutable profile changes start a new session/branch.
- `StudioProvider.generate(request, signal): AsyncIterable<StudioProviderEvent>`; request includes immutable input/asset manifest and no browser-authored provider state. `StudioProvider.edit(request, continuation, signal)` uses the same pinned profile and selected parent context. Events are `preview(bytes,mime,index)`, `completed(bytes,mime,continuation,usage)`, or safe refusal/failure; internal provider text/reasoning is never forwarded.
- `StudioSuggestion`: originalPromptDigest, suggestedPrompt, operation `enhance | new_idea`, usage; persisted as typed `studio_runs.result_json` with originalPromptDigest; bounded text-only call, explicitly accepted by user before replacing prompt. Suggestions never rewrite Text Copy or factual product/brand fields and never enqueue image generation.

## 3. Proposed persistence

Every tenant table has `(organization_id,id)` uniqueness, composite tenant FKs, forced RLS and authenticated SELECT only where described. JSON payloads have versioned Zod AND database validators. These records do not replace Asset Library or Campaign authority.

| Table | Required fields and invariants |
| --- | --- |
| `studio_documents` | id, organization_id, creator_id, title, revision, current_version_id nullable, settings JSON, archived_at, created_at, updated_at. Settings CAS on revision. Current version must belong to same document. |
| `studio_versions` | id, organization_id, document_id, ordinal, parent_version_id nullable, run_id unique, requested_campaign_id nullable, input_manifest JSON, input_digest, provider_profile_id, continuation_id, output_path/hash/mime/width/height/bytes, exact_text_copy, verification JSON, created_at. Immutable; unique document ordinal. Parent belongs to same document. A successful provider artifact only, never a partial frame. |
| `studio_runs` | id, organization_id, document_id, actor_id, operation `generate|edit|enhance|new_idea|export`, expected_revision, parent_version_id, immutable request JSON/digest, idempotency_key, profile_id, policy_version, reserved_minor/currency, actual_cost_minor nullable, state, lease_token, lease_expires_at, attempt, provider_request_id nullable, cancel_requested_at, result_version_id nullable, result_export_id nullable, result_json nullable (typed suggestion only), safe_failure_code, created_at, finished_at. Unique organization+actor+idempotency; replay mismatched digest returns conflict. |
| `studio_exports` | id, organization_id, studio_version_id, parent_export_id nullable, transform_version, transform JSON (`proportional_resize|contain_pad|reviewed_crop`), preset_version, output_path/hash/mime/width/height/bytes, created_at. Immutable measured derivative; consent is a separate append-only studio_export_acceptances receipt (organization/export/hash/transform digest/actor/time/idempotency). Same inputs reuse same export; any byte/encoding/transform change creates another. Source provider version/context unchanged. |
| `studio_run_events` | organization_id, run_id, sequence bigint, kind, safe_payload JSON, created_at; unique run+sequence. Append-only; sequence assigned in DB. Payload permits stage/preview ID/error code, not prompt, base64, signed URL or opaque continuation. |
| `studio_preview_frames` | id, organization_id, run_id, frame_index, private_path, content_hash, mime, width/height, expires_at; unique run+index. Decode/size-limit before storage. Never eligible as final/download/review/campaign source. |
| `studio_uploads` | id, organization_id, actor_id, reserved_path, state `reserved|ready|rejected|expired`, rights_attestation JSON/id, final_hash/mime/dimensions, expires_at. Finalized through authoritative byte intake. |
| `studio_continuations` | id, organization_id, document_id, version_id, parent_id nullable, profile_id, private_object_path/hash, provider_handle nullable, replay_expires_at nullable, state `usable|expired|deleted`, created_at. No authenticated SELECT; browser only sees computed edit availability/reason. |
| `campaign_selected_creatives` | id, organization_id, campaign_id, studio_version_id, studio_export_id nullable, content_hash, originating_run_id nullable, selected_by, idempotency_key, state `awaiting_campaign_setup|ready_for_review|blocked|superseded`, target_bundle_version_id/direction_key/slot JSON nullable, deliverable_version_id nullable, failure_code nullable, created_at. Unique campaign+Studio version+selected export identity (including native identity); non-null deliverable implies real validated slot. Selection/history remains auditable. |
| `studio_generation_policies` | id, organization_id, version, enabled, currency, per_run_ceiling_minor, window_ceiling_minor, window_seconds, max_pending, max_attempts, current pointer through organization-scoped lock. Immutable policy versions; no invented enabled budget defaults. |

Policy reservation ledger entries may be in `studio_runs` with transactional organization locks and indexed window sums; avoid introducing a second mutable spend counter unless required for performance. Unknown actual cost is null, not zero. Retain reservation for unknown paid outcome until explicit reconciliation.

## 4. Proposed RPC signatures and authority

All JSON inputs use named versioned schemas below. All mutation functions: empty search_path, schema-qualified references, explicit EXECUTE grants, tenant/member checks where user-called, deterministic errors, transaction-owned events. Worker calls additionally verify run ownership, active lease and allowed transition. No browser route uses a service-role client.

| RPC | Caller and result |
| --- | --- |
| `save_studio_document(target_organization_id uuid, input_document jsonb) returns jsonb` | authenticated `studio.edit`; `{id?,expectedRevision,title,settings}` → document/revision; stale → conflict. |
| `reserve_studio_upload(target_organization_id uuid,input_upload jsonb) returns jsonb` | authenticated `studio.edit`; declared kind/size/MIME/rights → uploadId/private reservation; signing route validates reservation. |
| `complete_studio_upload(target_organization_id uuid,target_upload_id uuid,input_receipt jsonb) returns jsonb` | worker only; byte-intake receipt/hash/dimensions against reservation → ready/rejected. User complete route requests verification, never asserts bytes valid. |
| `save_studio_generation_policy(target_organization_id uuid,input_policy jsonb) returns jsonb` | authenticated `studio.policy_manage`; explicit values → immutable version/current pointer. |
| `admit_studio_run(target_organization_id uuid,input_run jsonb) returns jsonb` | authenticated `studio.generate`; document/revision/parent/operation/idempotency/settings digest → runId/replayed/reservation or typed refusal. If campaign selected, require `campaign.edit` and same-tenant campaign now. |
| `claim_studio_run(target_run_id uuid,target_worker_id text,lease_seconds integer) returns jsonb` | worker only; bounded lease and token; existing spent/unknown attempt never blindly reclaimed for new paid request. |
| `heartbeat_studio_run(target_run_id uuid,target_lease_token uuid) returns boolean` | worker only; extends current live lease, never resurrects cancelled/completed run. |
| `append_studio_run_event(target_run_id uuid,target_lease_token uuid,input_event jsonb) returns bigint` | worker only; allowed event/stage transitions, bounded preview receipt, DB sequence. |
| `complete_studio_run(target_run_id uuid,target_lease_token uuid,input_result jsonb) returns jsonb` | worker only; validated final receipt+continuation+usage → immutable version, current pointer CAS, final event and accounting atomically. Preserve immutable requested_campaign_id as a pending link intent. If the selected native/export bytes are already final under admitted export settings, create the selection atomically; if fit/pad/crop acceptance is still required, return linkStatus awaiting_export_acceptance and create no usable Campaign selection yet. Suggestions complete without image version. |
| `fail_studio_run(target_run_id uuid,target_lease_token uuid,input_failure jsonb) returns jsonb` | worker only; safe code, outcome certainty, cost receipt → failed/unknown with correct reservation state. |
| `cancel_studio_run(target_organization_id uuid,target_run_id uuid) returns jsonb` | authenticated `studio.generate`; request cancellation only; worker settles actual outcome. Completed version is not deleted. |
| `create_studio_export(target_organization_id uuid,input_export jsonb) returns jsonb` | authenticated `studio.edit` admits version/preset/transform/idempotency as a deterministic export run with preassigned output ID and zero provider reservation; worker finalizes validated derivative through `complete_studio_export(target_organization_id uuid,target_export_id uuid,input_receipt jsonb)` with worker-only grant; preview+accept consent pins transformed hash. Worker verifies preassigned export ID against admitted export run before inserting final derivative. Exact-ratio proportional export can use the transform consent frozen at Generate; contain/pad or crop requires accept_studio_export after visible preview. Worker completion can never forge accepted_by. |
| `accept_studio_export(target_organization_id uuid,target_export_id uuid,expected_content_hash text,idempotency_key text) returns jsonb` | authenticated `studio.edit`; explicit fit/pad/crop preview consent → append-only acceptance receipt over immutable export identity and requested Campaign selection in one transaction after `campaign.edit` revalidation. Link failure returns visible blocked intent while retaining export; retry never regenerates. |
| `file_studio_creative_history(target_organization_id uuid,input_filing jsonb) returns jsonb` | authenticated `studio.edit` AND existing `asset.manage` permission; exact version/export/hash, folderId nullable, rights and idempotency → itemId/versionId, unreviewed. Explicit action only. |
| `select_studio_campaign_creative(target_organization_id uuid,input_selection jsonb) returns jsonb` | authenticated `studio.edit` AND `campaign.edit`; campaign/studioVersionId/studioExportId nullable/hash/idempotency → durable selection, awaiting setup when no real slot. |
| `create_campaign_draft_with_studio_creative(target_organization_id uuid,input_draft jsonb) returns jsonb` | authenticated `studio.edit` AND `campaign.create`; title, supplied brief fields, studioVersionId/studioExportId nullable/hash/idempotency → campaignId/selectionId in one transaction; NO generation or fabricated bundle/direction. |
| `resolve_campaign_selected_creative(target_organization_id uuid,target_selection_id uuid,input_target jsonb) returns jsonb` | worker only; target real bundle/direction/slot/expected hash → exact unreviewed deliverable or awaiting setup/blocked; validates authorized selection and current campaign state. |
| `reconcile_studio_run(target_run_id uuid,input_receipt jsonb) returns jsonb` | worker only; documented provider retrieval/known outcome settles unknown state without new generation. No arbitrary operator override to invent success. |

Use existing organization policy controls as the entry point for the bounded Studio preparation policy; no new standalone policy settings page. Where no compatible budget exists, expose an admin-only inline policy editor and an honest disabled-generation explanation, never seed an enabled allowance.

Proposed new permissions: `studio.read` to viewer/operator/admin/owner; `studio.edit` and `studio.generate` to operator/admin/owner; `studio.policy_manage` to admin/owner. Generation requires an enabled explicit policy in addition to permission. Native and versioned-export download follows `studio.read`; rights restrictions may refuse export without making the artifact disappear. Opaque continuation is never readable through that permission.

Existing mismatch to resolve in docs, not by silently changing grants: `context/04-domain-model.md` says operators cannot approve public actions; `src/domain/access/permissions.ts` gives operators `campaign.approve`, and `review_campaign_deliverable_version` checks that permission. Preserve current effective review rights in this slice, document them accurately, and keep `campaign.publish` separately enforced. Studio grants must not expand either permission.

## 5. APIs, events and concurrency

- New UI `/organizations/[organizationId]/campaigns/studio` and `/organizations/[organizationId]/campaigns/studio/[documentId]`; static segment precedence/active navigation tested against `[campaignId]`; GET `/api/organizations/[organizationId]/studio` lists cursor-paginated documents/versions; POST `/studio/documents`, PATCH `/studio/documents/[documentId]`; POST `/studio/uploads`, POST `/studio/uploads/[uploadId]/complete`; GET/PUT `/studio/policy`; POST `/studio/runs`; POST `/studio/runs/[runId]/cancel`; GET `/studio/runs/[runId]`; GET `/studio/runs/[runId]/events?after=N`; GET `/studio/versions/[versionId]/download?exportId=...`; POST `/studio/versions/[versionId]/exports`; POST `/studio/exports/[exportId]/accept`; POST `/studio/versions/[versionId]/asset-library`; GET `/studio/runs/[runId]/suggestion` (session-scoped exact suggestion/original prompt, not SSE payload); POST `/studio/versions/[versionId]/campaign-links`; POST `/studio/versions/[versionId]/create-campaign`.
- UI `editing` and `admitting` are ephemeral states before a persisted accepted run. Persisted states are `queued|preparing|generating|previewing|validating|ready|failed|cancel_requested|cancelled|outcome_unknown`; provider-independent DB transitions enforce that graph. Save valid final even when a particular run produces no pre-final frame, but record `missing_progressive_preview` capability failure; repeated absence disables qualification, never fabricate previews.
- SSE authenticates membership before connect and periodically during reconnect/heartbeat; permission revocation terminates visibility. Event IDs are persisted sequences. Reconnect snapshots run state then replays after cursor with duplicate suppression. A page reload does not submit a new paid run.
- Events: `studio.run.accepted`, `.references_prepared`, `.generation_started`, `.preview_available`, `.output_validated`, `.completed`, `.failed`, `.cancel_requested`, `.cancelled`, `.outcome_unknown`; plus `studio.campaign_link_created`, `.campaign_link_blocked`, `.campaign_link_resolved`. Final event follows durable transaction, never provider completion alone.
- Restrict one active image-producing run per document; suggestion runs may coexist with separate caps. Explicit edit of an older version creates a branch; never silently edit the latest. Save while generating does not rewrite admitted inputs. Completion advances current pointer only if expected revision/current version still match; otherwise save output as a historical branch and report that fact.
- Dispatch revalidates current access, reference rights/review and policy before sending bytes. Losing campaign edit permission must not discard a completed poster: record blocked link and display retry/setup status; never silently attach under revoked authority. Reference revocation after provider submission is recorded and blocks further reuse/export where rights require it, without falsifying past provenance.
- Idempotency digest includes operation, exact copy, channel-logo substitution manifest, primary reference, prompt, reference IDs/hashes, parent, profile, preset/transform dimensions and selected campaign. Replaying a key with a different payload is 409. Lease token fences every worker write; cancellation/disconnect must not retry a paid request. All provider error payloads stay server-private.

## 6. Storage, continuation, rights and retention

- Private `studio-assets` objects: `{organizationId}/{documentId}/{versionId}/{hash}.{ext}`; private `studio-previews`: `{organizationId}/{runId}/{frameIndex}-{hash}.{ext}`; private `studio-context`: continuation and marker/reference snapshots, worker-only. Upload reservation prefix uses organization/upload IDs. Bucket policies cross-check scoped DB ownership; signed links expire after 5 minutes and may be refreshed by authorized routes.
- Intake accepts PNG/JPEG/WebP only; effective per-upload ceiling is min(existing bucket/organization limit, application 15 MiB ceiling, qualified provider request-method limit after encoded overhead); actual dimensions use the intersection of current intake 200–8000 each edge and profile limits, EXIF normalization, MIME sniffing, decoding/re-encoding and decompression limits. SVG logos use existing validated rasterization or refuse unsupported input. Total serialized provider payload uses qualified profile limit; UI shows effective lower bound.
- A fresh uploaded reference requires attestation of authorized AI processing and intended use; it does not become approved Creative History. Product photography remains subject evidence, not historical creative. Approved history pins review/confirmed metadata; recheck dispatch eligibility. Never pass rejected history bytes or provider-side retrieval URLs from client input.
- Preserve provider-required ordered replay parts/opaque signature metadata or documented server handle, pinned API configuration, exact parent branch and original reference manifest. Do not persist/expose raw thought text. Qualification must prove replay can work without retaining hidden reasoning; otherwise reject that profile.
- Provider handles are accelerators, not sole artifact ownership. On expired context, show “Original editing context unavailable”; keep download/history; an explicitly chosen new-context branch is not marketed as same-context editing. No silent provider/model fallback mid-session.
- Proposed retention: complete outputs/provenance and campaign-linked versions persist until organization lifecycle deletion; archives hide, do not destroy. Private continuation retained with output unless a provider limit ends earlier, disclosed by replay_expires_at. Partial frames retained 24 hours after terminal run, failed upload objects 24 hours, events 30 days; final run/status/provenance remain. Cleanup is scheduled, scoped, retries safely and cannot delete referenced final artifacts. Provider-side retention/deletion obligations must be documented by qualification before enablement.

## 7. Campaign selected-byte handoff

`createCampaignService.create` in `src/modules/campaigns/application/service.ts` calls `enqueueGeneration`; NEVER reuse unchanged for Create campaign from Studio. New atomic draft+link operation may reuse lower-level schema semantics, but must emit no generation event/task or fabricated planning record.

Auto-link after completion and explicit Attach both pin selected `{studioVersionId,studioExportId|null,contentHash}`. For a preset requiring padding/crop, final readiness includes accepted conversion preview; auto-link pins those reviewed export bytes, not incompatible provider-native pixels. Until acceptance the version remains saved and link intent is awaiting_export_acceptance; accept_studio_export transitions it, with frozen target and current permission checks. Explicit Attach/Create also take studioExportId and expected hash; neither may silently choose another derivative. New draft or existing campaign without a real bundle/direction remains `awaiting_campaign_setup`. Campaign setup reads this selected creative as authoritative finished-source intent, not merely as inspiration. The concrete existing setup seam is `generateCampaignBundle` in `src/workflows/campaigns/generate-bundle.ts`: `dependencies.publisher.publish` is wired by `src/trigger/campaigns.ts` to `createCampaignVersionWriter(...).createVersion` in `src/modules/campaigns/infrastructure/repository.ts`, which invokes `create_campaign_bundle_version`. Add durable selected-resolution intent at successful bundle insertion; service it after the publisher returns and with a bounded recovery sweep. Draft+link itself never invokes generation; later explicitly requested governed Campaign preparation can create the real bundle. Once that real setup creates a compatible slot, resolver binds that SAME hash to an unreviewed deliverable; if terms/copy/placement conflict, show `blocked` with “Review campaign details”, never silently regenerate/replace it. A material image change is another Studio version and another explicit selection.

Extend `deliverableSourceSchema` with `{kind:'studio_version',studioVersionId,studioExportId:null|uuid,contentHash}` and a tenant FK. Extend the record RPC/readers/source resolver and review UI together. Keep existing not-null bundle/direction fields on actual deliverables; pending selections live outside them.

Introduce `deliverableRenderInputsSchema` union: legacy untagged compositor object parsed and canonicalized EXACTLY as today; new `{schemaVersion:2,kind:'studio_full_poster',studioVersionId,studioExportId:null|uuid,contentHash,inputDigest,providerProfileId,textCopyDigest,channelLogoSubstitutionDigest,referenceManifestDigest,exportTransformDigest:null|sha256}`. New version envelope is schemaVersion 2; readers accept legacy version 1. Never add discriminator/default fields to old parsed objects or rewrite old render_digest values. Golden fixtures assert old canonical JSON/digests byte-for-byte. New source requires new input arm and matching source/version/hash; no fake template/font/plate values.

Add `resolveDeliverableSource` reading immutable Studio object/hash for preview, download and existing exact-output review. Any existing publication consumer of deliverables must use this resolver and retain Tool Gateway policy; this project does not add a publisher, auto-publish, reserve media budget, or claim external publication works. Test source resolution with a fake gateway and known bytes. Real launch remains unavailable where its existing gates are unavailable.

## 8. Explicit Save to Asset Library

Studio history is automatic; Creative History filing is an explicit separate action. Extend `src/domain/campaigns/creative-history.ts` source union with `studio_version` including version/export/hash, and add nullable same-tenant source FKs to existing Creative History version records with exactly-one-source validation. Extend existing storage resolver/reader to sign this source without copying mutable files. New immutable `studio_history_filings` receipt records organization, selected artifact identity, history item/version, actor and idempotency; unique source artifact prevents retry duplicates. Filing uses the exact final/export bytes, never a preview. Output starts Unreviewed; existing human metadata confirmation/review/rights rules alone make it eligible for later reference selection. No automatic approval, folder verdict, or campaign review inheritance. Existing Creative History upload/render source rows remain readable.

Create private worker-validated source receipt before session-authorized `file_studio_creative_history` transaction, or verify immutable scoped version/hash directly in the transaction; do not grant browser arbitrary object-path writes. Filing requires existing `asset.manage` (verified in `20260909124757_creative_history_core.sql`); historical review requires separate `asset.review`. Neither is an invented `asset.write` alias. Test foreign folder/version, expired rights, repeated filing, source hash identity, and inability of unreviewed filed output to enter Approved designs.
