# Shared Business Memory implementation plan

- **Status: Draft — do not execute until Spec 023, ADR 0054 and this plan receive explicit approval.** The confirmed preference for automatic capture with distinct trust levels is not blanket implementation approval.
- **For the implementing agent:** use the executing-plans skill and implement sequentially with review gates. Do not start parallel agents unless separately requested. Repository instructions override skill defaults, including this bullet-only Execution Plan format and hosted-staging workflow.
- **Goal:** connect Channel Audit, Growth Intelligence and Campaigns through trustworthy shared context and durable capture, with visible provenance and no automatic truth or policy promotion.
- **Architecture:** extend existing memory, combine current source reads with governed episodes, atomically queue capture in source transactions, project through leased RPCs, and pin a bounded context manifest for each AI attempt.
- **Stack:** existing TypeScript strict mode, Zod 4, Next.js, Supabase/Postgres/RLS, Trigger.dev SDK 4.5.16, existing AI providers and pgvector. No new memory vendor, graph database, Redis implementation or model orchestration framework.
- **Spec:** [Spec 023](../../../specs/023-business-memory-shared-intelligence.md). Read [research](../../research/2026-09-10-business-memory-shared-intelligence.md) and [ADR 0054](../../../adrs/0054-business-memory-shared-context-and-governed-capture.md) with it. This plan defines execution steps; Spec 023 owns domain rules and schema requirements.

- **Global constraints:** hosted staging only; no `supabase start`, `db reset`, Docker, `pnpm db:types`, `git stash`, repository-wide formatting, provider calls before qualification, or git push. Do not change existing unrelated dirty files. Generate additive migrations with the CLI and edit database types narrowly by hand.
- **Global limits:** pack 24 entries/16,384 UTF-8 bytes/600 characters per summary; 50 candidates per section; section slots 6 current, 6 intent, 8 observations, 4 lessons; at most 3 unverified AI observation entries; projection document 8 KiB; ancestry 32 hops/100 roots; claim batch 25, due scan 100, lease 120 seconds; capture poll one minute, reconcile 15 minutes.
- **Global semantics:** acknowledgement is seen; planning is intent; source resolution is not success; approval is not publication; publication is not measured effectiveness. Human review cannot manufacture outcome evidence. Existing deterministic eligibility, ranking, money, policy and approval behavior stays authoritative.
- **Global source boundary:** capture from committed source records only, never raw worker outputs. New AI context excludes unqualified legacy memory. Rights-expired/withdrawn roots invalidate descendants and stored context snapshots. Initial purposes accept at most internal content and never private data in public searches.
- **Open assumptions proposed for approval:** extend the current module; use source-specific deterministic projections; conditional non-grounded Channel narration; actor-scoped personal feedback excluded from shared context; 90-day content/365-day permitted audit retention; review horizons 14/30/90 days as specified; Channel → Growth → Campaign delivery order; no broad event-publisher replacement. If any is rejected, revise the spec before code.
- **Blast radius:** memory domain/application/persistence/UI, source completion and triage RPCs, Channel narration/judge versions and context associations, Growth research/synthesis strict documents and fingerprints, Campaign generation provenance/lesson submission, Trigger task registration, permission catalogue, manual database types, RLS and retention cleanup. Deterministic report ingestion, metric arithmetic, execution policy and Tool Gateway authority are not redesigned.
