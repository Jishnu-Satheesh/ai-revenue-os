# Organization home: exact data and behavior contract

- **Authority:** Companion to `../specs/2026-09-11-organization-home-design.md`. All interfaces below are proposed additions, not claims about existing exports. The source evidence paths are real as of `.superdesign/organization-home/source-baseline.json`.
- **Scope:** Read composition and private previews only. The current full Digital Twin snapshot remains unchanged; the newly added Campaign/asset reads are bounded. Do not claim the entire existing snapshot loader is paginated.

## 1. Proposed public types

- Create `src/modules/organizations/application/home-types.ts` with the following named exports; all collections are readonly.
- `HomeSection<T>` is the discriminated union `{ status: "ready"; data: T; fetchedAt: string }`, `{ status: "failed"; code: "HOME_READ_FAILED" }`, or `{ status: "disabled" }`. Empty arrays belong to ready, never failed. Dates are canonical UTC ISO strings.
- `HomeImage`: `{ url: string; alt: string; width: number; height: number; expiresAt: string }`. The URL is a server-minted private preview; dimensions are positive integers. Never put a storage path or bucket name in this DTO.
- `HomeAsset`: `{ id: string; sourceKind: "poster_render" | "brand_reference"; label: string; sourceLabel: string; reviewLabel: string; reviewState: "approved" | "unreviewed"; recordedAt: string; image: HomeImage | null; sourceHref: string }`. Composite `id` uses `poster:<uuid>` or `reference:<version-uuid>`. Rejected references are omitted; no record is automatically approved.
- `HomeCampaign`: `{ id: string; title: string; objective: string | null; state: CampaignState; generation: CampaignGeneration; openable: boolean; updatedAt: string; actionLabel: "Review campaign" | "Continue draft" | "View campaign" | "View in Campaigns"; href: string; cover: HomeImage | null; coverLabel: "Finished render" | "Campaign image" | null }`. Reuse the existing imported `CampaignState` and `CampaignGeneration`, do not redeclare them.
- `HomeAttentionItem`: `{ id: string; sourceLabel: "Campaign" | "Organization"; title: string; reason: string; actionLabel: string; href: string }`.
- `HomeActivityItem`: `{ id: string; label: string; title: string | null; occurredAt: string; href: string | null; kind: "campaign" | "asset" | "organization" }`.
- `HomeGoal`: `{ id: string; name: string; target: string; deadline: string | null; scopeLabel: string }`. `target` is deterministic formatted text from saved goal unit/value, not an inferred result.
- `HomeDestination`: `{ key: "channels" | "growth" | "memory" | "integrations"; label: string; description: string; href: string }`.
- `HomePermissions`: `{ canCreateCampaign: boolean; canEditCampaign: boolean; canReviewCampaign: boolean; canManageCore: boolean }`. `canReviewCampaign` means the role permits entry to the review workflow; it is not an approval envelope or permission to publish.
- `OrganizationHomeView`: `{ organizationId: string; name: string; description: string | null; status: string; timeZone: string; currency: string; logo: HomeImage | null; locations: readonly { id: string; name: string; kind: string }[]; branchlessConfirmed: boolean; goals: readonly HomeGoal[]; focusGoalId: string | null; permissions: HomePermissions; campaigns: HomeSection<readonly HomeCampaign[]>; assets: HomeSection<readonly HomeAsset[]>; assetsPartial: boolean; attention: readonly HomeAttentionItem[]; attentionIncomplete: boolean; destinations: readonly HomeDestination[]; activity: readonly HomeActivityItem[] }`.
- Create Campaign-owned `src/modules/campaigns/application/home-preview-types.ts`. Export `CampaignHomeRecord = { item: CampaignListItem; cover: PrivatePreviewImage | null; coverLabel: "Finished render" | "Campaign image" | null }`. Define `PrivatePreviewImage` here; `HomeImage` aliases it in Organizations. **Campaign code must not import Organizations home types.**
- `PrivatePreviewImage` has precisely the five fields defined for `HomeImage`. `CampaignHomeRecord.coverLabel` is declared directly as `"Finished render" | "Campaign image" | null`. `AssetHomeRecord` has the same fields as `HomeAsset`; declare the full shape in Campaign-owned types and alias `HomeAsset` in Organizations. This establishes one declaration for each shared shape and no module cycle.
- `CampaignHomeReads`: `{ campaigns: HomeSourceResult<readonly CampaignHomeRecord[]>; posters: HomeSourceResult<readonly AssetHomeRecord[]>; references: HomeSourceResult<readonly AssetHomeRecord[]>; logo: PrivatePreviewImage | null }`, with Campaign-owned `HomeSourceResult<T>` having the same union shape as `HomeSection<T>`; Organizations aliases it rather than copying the declaration.

## 2. Required existing seams and traps

- Required organization context: `getOrganizationContext` in `src/lib/api/organization-context.ts`; use its resolved organization ID, effective membership role, session client and actor. Do not query only explicit organization memberships, which would exclude agency-derived access.
- Snapshot: `getDigitalTwin` in `src/modules/organizations/infrastructure/repository.ts`; returns organization, branches, profile, goals, facts, constraints, policies and up to 50 audit events. Preserve its use for existing management and core error behavior.
- Permissions: `hasOrganizationPermission` in `src/domain/access/permissions.ts`; existing `getOverviewPermissions` in `src/modules/organizations/application/overview.ts` owns core/policy/lifecycle editing distinctions.
- Campaign lifecycle: `toCampaignListItem` and `toGeneration` in `src/modules/campaigns/application/studio-view.ts`. `readCampaignList` in `infrastructure/studio-reader.ts` loads the whole list and versions; do **not** call it for a three-item home preview.
- Existing `createCampaignReadRepository` can read an individual campaign, an individual bundle version, and the latest generation run. Reuse these bounded individual-record operations, but not its unbounded `listCampaigns` or `listVersions`.
- Campaign list items have no image URL and no latest bundle-version ID. The new reader must retain the selected version ID internally while building covers. Do not pretend `item.version` is the UUID.
- Existing `asset-preview.ts` signs all `campaign_assets` in one bundle. Home requires one chosen image, so do not invoke that full-version reader to get one cover. Reuse its private-bucket/600-second pattern, not its unbounded read.
- Existing `asset-library-repository.ts` scans references, versions and reviews. Do not call `listReferences` and slice in memory; queries must be bounded before execution.
- Current AssetWorkspace has no working preview URL for references and no finished-render detail route. Home supplies a read-only Dialog; reference destination is `/assets`, poster destination is the exact campaign version.
- `campaign_poster_renders.state="rendered"` proves a renderer produced output. `verification` is technical evidence, not a creative-review verdict. Do not read raw `text_values`, `verification`, or refusal payloads merely to build a thumbnail.
- `creative_items` and `creative_item_versions` migration files exist, but no corresponding current application read surface was found. This slice neither relies on that unfinished UI nor invents its contracts. Do not change ADR 0049 or build Creative History while executing this plan.

## 3. Gates, entry and orchestration

- Proposed `buildOrganizationHomeView` in `src/modules/organizations/application/home-service.ts` consumes `{ snapshot: DigitalTwinSnapshot; role: OrganizationRole; organizationId: string; now: string; sources: CampaignHomeReads; gates: { campaigns: boolean; growth: boolean; integrations: boolean } }` and returns `OrganizationHomeView` synchronously. `sources` contains already-settled results, not a Supabase client.
- Put asynchronous read orchestration in `src/modules/organizations/infrastructure/home-loader.ts`: `loadOrganizationHome(input: { supabase: SupabaseClient<Database>; organizationId: string; role: OrganizationRole; snapshot: DigitalTwinSnapshot; correlationId: string; now: string }): Promise<OrganizationHomeView>`.
- After membership resolves, evaluate `isCampaignsEnabled(orgId)`, `hasGrowthIntelligenceAccess(orgId, "market")`, `isIntegrationHubEnabled(orgId)`, and relevant permission grants. Do not call a gated module merely to learn it is disabled.
- Campaign reads require Campaign rollout plus `campaign.read`. The loader passes `canReadArtwork=hasOrganizationPermission(role,"asset.read")`; false skips every cover metadata/review/signing call while retaining campaign text. References/logo require Campaign rollout plus `asset.read`. Poster gallery requires both `asset.read` and `campaign.read`, plus the rollout. This avoids exposing a campaign through its image when the campaign read permission is absent.
- New campaign requires Campaign rollout plus `campaign.create`. Draft continuation additionally requires `campaign.edit`. Review wording requires `campaign.approve`; operators/viewers get View campaign. **Review means navigation only, never approval.**
- Around-your-business visibility: Channels uses `channel.read`, verified in `src/domain/access/permissions.ts`. Growth uses `growth_intelligence.read` plus market gate; Memory uses `memory.read`; Integration Hub uses `integration.read` plus its gate.
- Initialize source promises independently and `Promise.allSettled` before composition. Catch domain errors into failed source states and emit safe structured logging. A failed logo read/sign is a null logo, not a failed home. A partial gallery is ready with `assetsPartial=true`; both attempted gallery sources failing is failed. Disabled sources never count as failures.
- `now` is one request timestamp used for lease interpretation, fetchedAt and URL expiry; format display dates using `snapshot.organization.default_timezone`. Use the actual clock after a successful sign for `expiresAt` if signing took significant time; never grant longer than 600 seconds.

## 4. Campaign query recipe

- Create `src/modules/campaigns/infrastructure/home-campaign-reader.ts`. Export `readHomeCampaigns(input: { database: HomeCampaignPersistence; read: CampaignReadPort; storage: HomePreviewStorage; organizationId: string; now: string; correlationId: string; canReadArtwork: boolean }): Promise<readonly CampaignHomeRecord[]>`.
- `HomeCampaignPersistence` is a structural query port naming only `campaigns`, `campaign_bundle_versions`, `campaign_poster_renders`, `campaign_assets`, and `creative_asset_reviews`. Support `select`, `eq`, `order`, `limit`, `is`, `not` as required by the recipes. Chain results are thenable `{ data: unknown; error: unknown }`. No mutation or service-role capability belongs to this port.
- First query: `campaigns`, select `id,organization_id`, filter org, order `updated_at DESC`, `id DESC`, limit **3**. Validate rows with Zod UUIDs and tenant equality. For each ID, call existing `read.getCampaign(orgId,id)`.
- Per selected campaign, query `campaign_bundle_versions`, select `id,organization_id,campaign_id`, filter org+campaign, order `version DESC`, `id DESC`, limit **1**. Validate all linkage. If present use `read.getVersion(orgId,versionId)` and verify `version.campaignId===campaign.id`. If absent call existing `read.latestGenerationRun(orgId,campaign.id)`.
- Null/missing campaign after selection (concurrent disappearance or refusal) becomes a safe campaign-source failure; never fabricate a record. A missing selected version similarly fails rather than showing another version. Genuine zero version rows is the normal no-proposal case.
- Validate campaign state against `CAMPAIGN_STATES`, then call `toCampaignListItem(campaign, latest, run, now)`. Its missing-version/expired-lease behavior is authoritative.
- Cover per version: query `campaign_poster_renders` selecting `id,organization_id,campaign_id,bundle_version_id,output_storage_path,output_width_px,output_height_px,rendered_at`, filter org+campaign+version, `state=rendered`, non-null output path, order rendered_at DESC then id DESC, limit **1**. Validate dimensions/linkage before signing. Label **Finished render**.
- Only if there is no qualifying poster row, query `campaign_assets` selecting `id,organization_id,bundle_version_id,asset_key,storage_path,width_px,height_px,mime_type,created_at`, filter org+version, order created_at DESC then id DESC, limit **1**. Look up the latest `creative_asset_reviews` for that exact campaign_asset ID, org and subject_kind, ordered reviewed_at DESC then id DESC, limit **1**. Rejected means no cover. Other verdicts permit a cover labelled **Campaign image**. Do not retry with older assets after rejection.
- A cover query/sign failure yields null cover and a safe logged preview failure; campaign text remains ready. An error reading the campaign/version/generation state fails the Campaign section.
- Never reuse a render's URL under a different campaign merely because titles or filenames match. A cover signed URL must come from a validated database row for that selected current version.
- Bounded query count for three campaigns: one ID query plus at most seven metadata queries per campaign; no query count scales with historical campaign/version count. Storage signing is separately bounded to at most three covers. Follow these bounded individual-record operations; do not refactor shared repository APIs for batching in this slice.

## 5. Asset gallery query recipe

- Create `src/modules/campaigns/infrastructure/home-asset-reader.ts`. Export `readHomePosterAssets(input: { database: HomeAssetPersistence; storage: HomePreviewStorage; organizationId: string; now: string; correlationId: string }): Promise<readonly AssetHomeRecord[]>`, `readHomeReferenceAssets` with the same signature, and `readHomeLogo` returning `Promise<PrivatePreviewImage | null>`.
- `HomeAssetPersistence` names only `campaign_poster_renders`, `campaigns`, `organization_brand_assets`, `organization_brand_asset_versions`, `creative_asset_reviews`. It adds the bounded `.in` operation (at most four IDs) to the recipe's query port where useful. Keep parent linkage checks explicit.
- Posters: select `id,organization_id,campaign_id,bundle_version_id,template_key,script,output_storage_path,output_width_px,output_height_px,rendered_at` from rendered poster rows with non-null output path for org, order rendered_at DESC then id DESC, limit **4**. Validate all rows. Resolve up to four parent campaign titles via one org-filtered `.in("id", ids)` query. Missing/inaccessible parent means omit that candidate and log a safe linkage failure. Do not expose its title or URL.
- Poster gallery label: `<campaign title> · <template_key> · <script>`; use the real template key and script, not an invented campaign-artwork title. Source label **Finished poster render**, review **Review not recorded**. Preserve separate render records even when the artwork looks similar; do not infer duplicates from titles or bytes.
- Poster destination: `/organizations/{orgId}/campaigns/{campaignId}?version={bundleVersionId}` with the verified `version` query key from `src/app/(platform)/organizations/[organizationId]/campaigns/[campaignId]/page.tsx:25`.
- References: select `id,organization_id,label,asset_role,archived_at,created_at` from `organization_brand_assets`, org filter, `archived_at IS NULL`, order created_at DESC then id DESC, limit **4**. This is explicitly “recent references,” not an inventory total or latest activity across all versions of old parent records.
- For each selected parent, select its latest **usable** `organization_brand_asset_versions` row with org+brand_asset_id filters, `is_usable=true`, order version DESC then id DESC, limit **1**. Select `id,organization_id,brand_asset_id,version,storage_path,mime_type,width_px,height_px,created_at`. Missing usable version omits that candidate.
- Per selected version, select latest `creative_asset_reviews`, fields `id,organization_id,subject_id,subject_kind,verdict,reviewed_at`, with org+subject_id+`subject_kind=brand_asset_version`, order reviewed_at DESC then id DESC, limit **1**. Match exactly the sort in `asset-library-repository.ts`; absent review is unreviewed. Rejected omits candidate, approved labels approved, unreviewed labels unreviewed. Never select an older approved review.
- Reference `recordedAt` uses selected version `created_at`; label uses saved parent label; destination is `/organizations/{orgId}/assets`. Source **Brand reference** covers logo/product/venue/team/other without renaming them Creative History.
- Combine up to four poster + four reference records; sort recordedAt DESC then composite id ASC; take **4**. No duplicate placeholders to fill the grid. A latest-candidate rejection may leave fewer items; do not scan the whole organization looking for four attractive pictures.
- Query/signing bounds: poster rows <=4, parent IDs <=4, reference parents <=4, version rows <=1 per parent, reviews <=1 per selected version. Sign at most four validated images per source in one batch per bucket, before final merge: at most eight candidate signatures overall. Document that bound in tests; no unbounded candidate scan or signing loop is permitted.
- A corrupt tenant/linkage row fails its source. A known unusable/missing version is an omission, not corruption. Inaccessible parent campaign is omitted without revealing the rejected row. No raw query error goes into the DTO.

## 6. Logo and private image contract

- Logo candidates: active `organization_brand_assets` with `asset_role=logo`, org filter, order id ASC, limit **2**. Two candidates means ambiguous: no automatic logo. Zero means name-only masthead. Exactly one proceeds to latest usable version and its latest review, using the reference recipe; only current `approved` qualifies.
- Do not search `brand_context` for guessed `logoUrl` keys; no canonical typed field was found. Do not promote a product photograph or generate an icon to fill the logo slot. A missing/ambiguous logo is not a setup error.
- `HomePreviewStorage` exposes only `storage.from("brand-assets" | "campaign-assets").createSignedUrls(paths,600)`. Existing private storage buckets remain private. URLs are a bearer capability: never persist them in an application cache, HTML fixture, logs, analytics, resume file or source-baseline JSON.
- References and logo use `brand-assets`; generated assets and rendered posters use `campaign-assets`. Paths come exclusively from validated tenant-scoped records. Require the recorded path to begin with `organizationId + "/"` and reject traversal segments; never accept a client-supplied URL/path/bucket.
- Per-path signing failures affect only the corresponding image. Reject unexpected returned paths; map by exact path, not response position. Shared same-path candidates may reuse one signature in the request but retain their separate record identity.
- Browser `<img>` errors set only that image's visible fallback. Use a small client `HomePreviewImage` wrapper with `onError`; do not retry automatically forever or refetch the whole route for each broken image. A user Retry refreshes server props.
- Production previews use ordinary private image delivery consistent with existing Studio; do not route signed URLs through an optimizing public CDN cache. If using Next Image, use the established unoptimized/private pattern; do not add wildcard remote patterns.

## 7. Pure presentation rules

- Proposed `buildOrganizationHomeView` uses snapshot plus source results, role and gates, then constructs all hrefs from verified UUIDs. Never carry arbitrary `href` from an LLM, audit payload or source JSON.
- Header description is `snapshot.profile?.value_proposition?.trim() || null`. Status from organization.status. Locations are only `is_active=true` branches. List `name` and `kind`; do not stringify operating hours/contact metadata. Header timezone/currency come from organization, not the first branch.
- Goals: organization scope first only for focus; full list sorted priority ASC then id ASC. A branch-scoped goal's label resolves its matching branch name, otherwise **Branch goal**. Render targets as `Intl.NumberFormat` of `target_value`, a space, the saved `unit`, and optional `currency` as a separate suffix. Do not divide by 100 or relabel the unit. The existing goal editor stores the numeric input directly; this slice preserves that meaning.
- Attention derivation uses the three selected campaigns: generation failed/stalled rank0, state blocked/needs_data rank1, state ready_for_review rank2. Deduplicate by campaign ID, choose lowest applicable rank, sort by rank then updatedAt DESC then id DESC, take 3. Every no-version link opens portfolio.
- When there is room, missing profile description and absent goals may contribute organization context prompts only for `canManageCore`. Use snapshot profile/goals directly, not the old economics-driven `buildOverviewActionQueue`, which would fabricate financial blocking copy here.
- Caption count is number displayed plus **shown**. `attentionIncomplete` is true if an attempted campaign source failed. Do not show “nothing needs attention” while it is true.
- Activity candidates: selected campaigns' updatedAt; gallery candidates' recordedAt; allowed snapshot audit events. Allowlist exact event names `organization.created`, `branch.created`, `business_profile.updated`, `goal.created` with respective labels **Organization created**, **Location added**, **Business profile updated**, **Goal added**. Unknown events are omitted. Resolve goal/branch names by same-organization snapshot ID only. No use of audit payload or actor identity.
- Activity key prefixes `campaign:`, `poster:`, `reference:`, `audit:` avoid cross-table UUID collisions. Sort timestamp DESC then key ASC; dedupe by composite key, take 5. Missing source histories do not synthesize updates. Link organization events to management only for permitted roles; use null href for viewers. View goals/locations remain available through the explicit home controls.

## 8. Deliberate non-changes

- No finance summary, revenue trend or reporting-window control on this first home slice. Performance stays available through Channels and Growth Intelligence; this is an explicit adaptation to the newly approved organization-home purpose.
- No new cross-module unread/activity store, organization-wide approval count, team-presence feature, task manager, onboarding score, real-time subscriptions, research invocation or automatic campaign work.
- No schema correction to Creative History, no shared sidebar edit, no changes to Channel/Growth Intelligence loaders, and no migration/type-generation workaround. Findings outside the home go in the handoff report rather than silently widening execution.
