## The end-to-end write, which is the point of the feature

Driven entirely through the browser, not through a script:

1. `/onboarding` → Customer context → **Brand assets**: typed a primary colour,
   wrote a rule, marked it **Absolute**, added a restricted term, pressed
   **Save and continue**.
2. `PATCH .../onboarding/sections/brand_assets` returned **200**, carrying
   exactly `palette: {primary:"#c8102e"}`,
   `brandRules: [{text:"Never imply a medical benefit", strength:"hard"}]`,
   `restrictedTerms: ["best in dubai"]`.
3. The row landed in `organization_brand_guidelines` under RLS, written as the
   signed-in owner, with `updated_by` set.
4. The audit trigger fired: `brand.guidelines_updated`,
   `{"operation":"INSERT","ruleCount":1,"paletteSlots":1,"restrictedTermCount":1}`
   — counts, never the rule text.
5. `load_campaign_creation_facts`, called as that same member, returned:

   ```
   hardConstraints: ["Never imply a medical benefit"]
   softConventions: []
   restrictedTerms: ["best in dubai"]
   palette:         {"primary":"#c8102e"}
   brandVoice:      "Warm, Direct, Conversational, Minimal"
   ```

**This is the first time in the repository's history that those three keys have
carried a value.** They have been read by this function, rendered into the image
prompt and checked by the content policy since generation was written, and
nothing had ever written them.

6. The Asset Library's **Brand Guidelines** tab then rendered the same record:
   the colour as a filled swatch, the rule under **Absolute**, and the term
   under Absolute beside a "Never write" badge, with **Preferred** reading
   "None set."

Note: this left a real guidelines row on the dev organization. It is honest
brand data and it is what generation will now use for that organization; delete
it from the tab if it is not wanted.

## Defects found in the browser and fixed

- **The fourth tab was unreachable on a phone.** Three tabs fitted; four did
  not. The strip measured 471px inside a 390px viewport with `overflow-x:
  visible`, so **Brand Guidelines** was clipped — including when a deep link
  had selected it. The strip now scrolls and each trigger holds its width.
- **A failed save was reported off-screen.** `SectionForm` rendered its
  destructive alert at the top of the scrolling body while the buttons sit in a
  pinned footer, so an operator who had scrolled to press Save saw nothing at
  all. Observed live: two saves failed and the form looked idle. The alert now
  renders in the footer beside the button that was pressed.
- **An unset palette read as a brand whose colours are black.** `input[type=color]`
  cannot show "unset", and three black swatches under three identical
  placeholders looked like a filled palette. Unset slots are now drawn faded
  with a dashed edge, carry distinct example placeholders, and say "Not set."
- **The restricted-terms input was named by its placeholder.** Its label
  carried an `id` but no `htmlFor`, so assistive technology announced
  "best in dubai" as the field name.

## A false alarm worth recording

The first browser save returned **404** from
`PATCH .../onboarding/sections/brand_assets`, as did every Creative History
read. The routes existed and exported the right handlers. It was a stale
Turbopack dev cache: after `rm -rf .next/cache` and a restart, the same probes
returned 401/405 — route present — and the save returned 200.

If API routes 404 in dev while the files plainly exist, clear the cache before
investigating the code.
